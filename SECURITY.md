# Security Policy

## Supported scope

The current `main` branch and the latest releases are supported. Older versions and modified builds are checked on a best-effort basis; no guaranteed support.

In scope: the tunnel implementation, pluggable transports and the scripting engine, exit-node backends, codec, CI workflows and build scripts. Real-network deployments and third-party configurations are out of guaranteed support.

## Reporting a vulnerability

1. Open [Security Advisories](https://github.com/saymer-alt/OpenFlux/security/advisories/new).
2. Use **Report a vulnerability** — the preferred private channel; reports never appear in public Issues.
3. **Never publish** exploitation details in a public issue, PR or discussion.

## What to include in a private report

- Affected version, platform and assumed impact.
- Minimal reproduction steps with **synthetic**, not real, secrets.
- Impact assessment and a safe remediation suggestion, if known.

**Do not upload** real private keys, subscriptions, passwords, private logs or third-party infrastructure details.

## Coordinated disclosure

Please do not publish exploitable details before a fix is agreed. Response times are best-effort; the project is maintained on a non-commercial basis.

Regular bugs and feature requests go through [Issues](https://github.com/saymer-alt/OpenFlux/issues/new/choose).
